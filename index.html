openwrt-spectral · ath10k spectral scan

See the RF around your router.

spectrald reads the ath10k spectral-scan FFT engine from debugfs, converts every frame to per-bin dBm and serves a live waterfall to LuCI. Two modes: a continuous waterfall of the serving channel, and a channel sweep that scans 2.4 / 5 GHz and stitches the per-channel FFTs into a panorama.

  • OpenWrt 25.12 · apk
  • arm_cortex-a7_neon-vfpv4
  • ath10k · QCA4019
  • 64–256 FFT bins
  • signed apk feed
  • MIT · kmod GPLv2

CI builds and signs the feed from main with an ECDSA P-256 key; authorize the key once (see Install). The spectral kmod in the extra feed is tied to one kernel version — read the kernel module section before enabling it.

What it is

Every 802.11ac Qualcomm Atheros radio can report FFT data from its baseband. The ath10k driver exposes those frames in /sys/kernel/debug/ieee80211/phyX/ath10k/spectral_scan0 — but only if it was built with CONFIG_ATH10K_SPECTRAL. This project turns that byte stream into a usable spectrum view.

Live FFT waterfall

64, 128 or 256 bins per frame, converted to dBm with the fft_eval-compatible formula, aggregated into a colour waterfall with a max-hold trace.

Channel sweep

Scans a channel list with iw and stitches the per-channel FFTs into a single panorama — 2.4 GHz ch 1–13, 5 GHz ch 36–165, a fast seven-window 5 GHz preset, or a custom list.

ubus API

spectral status/start/stop/get returns JSON rows of u16 dBm values. The LuCI view is just one client; scripts can poll the same object.

Small daemon

One small C binary under procd, no Python, no websocket, no extra web server. Idle when not scanning; stops itself 60 s after the last poll.

LuCI view

Canvas waterfall plus spectrum, auto dBm range, palette selection, and mode/bins/radio controls under Status → Spectrum.

Reversible

Stopping the scan writes disable to the driver and leaves the radio on its serving channel. Only the optional kmod replaces a stock file.

Install

Run these on the router over SSH. The feed is a static apk repository served by GitHub Pages; its indexes are signed with the project's ECDSA P-256 key, so package checksums are covered. Authorize the key once and apk verifies every download — no --allow-untrusted needed.

Quick install

Then open LuCI → Status → Spectrum. For a CLI-only setup install just spectrald.

Signature & trust

Both feed indexes are signed with the project's ECDSA P-256 key; apk verifies each package against the checksums covered by the signed index. The public key is served next to the .adb index:

The private key exists only as a GitHub Actions secret; it is not in the repository. The same key is used for future feed builds. If you prefer to keep the key out of the router's global keyring, you can also pass --keys-dir to a dedicated directory instead of installing it under /etc/apk/keys/.

Remove the repository and key

The installed packages stay; use apk del spectrald luci-app-spectral to remove them.

Spectral-enabled kmod (extra feed)

Read this before installing. The kernel module replaces the stock kmod-ath10k-ct package with a build that enables CONFIG_ATH10K_SPECTRAL. It is tied to one exact kernel version (6.12.112 with OpenWrt's kernel ABI), is not an upstream OpenWrt package, and can break Wi-Fi if the module or kernel do not match. The kmod feed index is signed with the same key as the main feed (authorize it first, see Install). Keep a way to reach the router over Ethernet while testing, and read the recovery steps first.

Why a custom kmod is needed

OpenWrt only compiles the ath10k spectral code when CONFIG_PACKAGE_ATH_SPECTRAL is set (package/kernel/mac80211/ath.mk), and the stock image ships it disabled. The driver's spectral.c and the 10.4 WMI commands are already present; the kernel side needs relayfs, which stock 25.12 kernels already provide (CONFIG_RELAY=y). So the fix is a kmod rebuild, not a kernel rebuild.

Recovery: restore the upstream kmod

If the Wi-Fi AP does not come back, restore the stock package and reboot. A copy of the official OpenWrt kmod is published next to the feed (same package, spectral disabled):

Official upstream copy: downloads.openwrt.org kmods/6.12.112-1-1ef…/kmod-ath10k-ct-… · SHA-256: b1f261de4da11583a77eea4dbe056b38188f15920804d85bb71383e78c335436.

If Wi-Fi is down and SSH is unreachable: connect a computer to a LAN port (Ethernet) and SSH to 192.168.1.1, then run the commands above. If the router does not answer at all, boot into OpenWrt failsafe mode (power-cycle and press the reset/failsafe button as instructed by the bootloader) or reinstall the stock image with sysupgrade. Keeping a recent configuration backup is recommended before touching kernel modules.

Remove the kmod feed again

The kmod binary is a build of the GPLv2 ath10k-ct driver as packaged by OpenWrt's feeds/base/kernel/ath10k-ct. The build recipe is in feeds/kmods/README.md in the repository; no kernel patches are applied. The daemon and LuCI app are MIT-licensed.

Usage

The LuCI view is a client of the spectral ubus object; everything can be scripted.

Single channel

Channel sweep

Presets: 2g (ch 1–13, 64 bins), 5g (ch 36–165, 256 bins), 5g-fast (seven 80 MHz windows). Sweep mode briefly takes the radio off-channel for each scan; expect small client hitches and lower throughput while it runs. The panorama rows fade (1 dB per row) so the waterfall shows the sweep in progress.

LuCI

Status → Spectrum. Pick Mode (single channel or a sweep preset; the radio and FFT bins are selected automatically), press Start, and adjust the dBm range or colour map as needed. The daemon stops itself 60 s after the last poll.

How it works

  1. ath10k firmware FFT / phyerr frames
  2. driver spectral_scan0 relay, TLV records
  3. spectrald dBm conversion, 10 rows/s
  4. ubus / rpcd JSON rows, admin ACL
  5. LuCI canvas waterfall + spectrum

Troubleshooting & FAQ

There is no spectral_scan0

The running ath10k kmod was built without CONFIG_ATH10K_SPECTRAL. Install the spectral kmod and reboot, or build your own image with CONFIG_PACKAGE_ATH_DEBUG=y and CONFIG_PACKAGE_ATH_SPECTRAL=y (and CONFIG_PACKAGE_MAC80211_DEBUGFS=y). check dmesg | grep ath10k if it still does not appear.

apk says “UNTRUSTED signature”

The repository key is not in /etc/apk/keys/. Download openwrt-spectral.pem from the site root into that directory (see Signature & trust) and run apk update again. The feed indexes are signed; --allow-untrusted should not be needed. Only the local stock-recovery .apk may require it if your image lacks OpenWrt's own release key.

The kmod refuses to install

Its dependency is the exact kernel 6.12.112~1ef2780854971e23a655b05e5b5c3630-r1. If you upgraded the kernel or run another OpenWrt release, the feed's kmod is the wrong build. Do not force it; build a matching kmod instead (recipe in the repository).

The 5 GHz AP did not come back after a manual module reload

That is the known hot-reload failure mode: hostapd's AP vdev is left in an inconsistent state (Match already configured / Failed to set beacon parameters). Reboot the router instead of rmmod/insmod. The module itself loads normally at boot.

The waterfall is empty or only noise

Check ubus call spectral status: running should be true, samples should increase and cols should be non-zero. A very busy channel can reduce the sample rate. For 80 MHz channels use 128 or 256 bins — 64 bins is not valid at 80 MHz. The dBm values are firmware estimates and can sit below the reported noise floor; the view auto-ranges.

Does sweeping disconnect clients?

It can cause brief interruptions: each scan takes the radio off its serving channel for a short dwell. Use single-channel mode for continuous monitoring of your own channel; use the sweep when you need to look across channels.

Does the daemon need to stay enabled?

The procd service stays enabled but does nothing until start is called, and it stops the scan after 60 s without a get poll. Disable it with /etc/init.d/spectrald disable.
